# Проверка open source лицензий

Сайт для юриста: находит сторонние компоненты программы, определяет их лицензии и показывает, какие обязанности и конфликты возникают при выбранной модели распространения. Результат выгружается отчётом в Word и таблицей CSV.

[Открыть сайт](https://goodlike2882.github.io/oss-license-check/)

## Что умеет

- Читает папку проекта прямо в браузере: `package-lock.json` и `node_modules`, `composer.lock`, установленные пакеты Python (`METADATA`), `requirements.txt`, `pom.xml`, `go.mod`, `Cargo.lock`, папку `vendor`, SBOM в форматах CycloneDX и SPDX (JSON).
- Определяет лицензию по метаданным пакета, по тексту файла LICENSE (около 30 распространённых лицензий) и по пометкам `SPDX-License-Identifier` в исходниках. Пометка чужой лицензии в собственном коде проекта выводится отдельной строкой: так находятся скопированные файлы.
- Разбирает выражения SPDX (`MIT OR Apache-2.0`, `GPL-2.0-only WITH Classpath-exception-2.0`) и устаревшие названия (`Apache 2.0`, `GPLv3`, классификаторы PyPI).
- Оценивает каждый компонент с учётом модели распространения (копии передаются, онлайн-сервис, только внутри компании), способа использования (библиотека, статическая сборка, отдельная программа, инструмент разработки), изменений в компоненте и лицензии самого продукта.
- Находит конфликты на уровне продукта: закрытый продукт с GPL-кодом, AGPL в закрытом сервисе, GPL-2.0-only рядом с Apache 2.0 и GPL-3.0, лицензии, несовместимые с GPL, запрет коммерческого использования.
- Собирает отчёт .docx: итог, конфликты с объяснением и тем, что сделать, обязанности по лицензиям, перечень компонентов, формулировку для лицензионного договора (ст. 1286.1, 431.2 ГК РФ) и ограничения анализа.

## Чего не умеет

- Не находит фрагменты чужого кода, скопированные без пометок: для этого нужна база исходного кода, как у коммерческих сканеров.
- Не проверяет уязвимости.
- Видит вложенные зависимости, только если в проекте есть lock-файл или установленные пакеты.
- Правила рассчитаны на типовые случаи. Спорные вопросы, например где граница между «отдельной программой» и производным произведением, решает юрист.

## Данные

Файлы читаются в браузере через File API и не отправляются на сервер. Сайт не использует cookie и счётчики, шрифты и библиотеки лежат в этом же репозитории. Подробнее — в [политике конфиденциальности](https://goodlike2882.github.io/oss-license-check/privacy.html).

## Устройство

Статический сайт на GitHub Pages без сборки:

- `assets/licenses.js` — база лицензий (категории, обязанности, совместимость) и правила оценки;
- `assets/scanner.js` — чтение форматов и распознавание текстов лицензий;
- `assets/report.js` — отчёт .docx (Office Open XML через JSZip) и CSV;
- `assets/app.js` — интерфейс.

Сторонние компоненты: шрифты IBM Plex (SIL Open Font License 1.1), JSZip (MIT).
